**ZeroTrade 仕様書（初版）**

---

### 1. 概要

| 項目 | 内容 |
|------|------|
| システム名 | **ZeroTrade** |
| 目的 | ドル円を中心としたFXおよび株式の自動売買を、ルール徹底・リスク管理を強制した形で実行するベースシステムを構築する |
| 対象市場 | FX（USDJPY中心）、日本株、（将来）米国株 |
| 対象外 | 仮想通貨（メインスコープ外。将来の拡張用にアダプタの余地は残す） |
| 設計思想 | 監視時間不足やルール破りをシステム側で防ぐ。裁量の介入を最小化し、証拠金管理・損失制限を強制する |

---

### 2. スコープ

**やる範囲**
- ブローカー抽象化による複数取引所対応
- ルールベース戦略の実行
- 厳密なリスク管理（ポジションサイズ・最大損失・証拠金使用率）
- バックテスト基盤
- ペーパートレード / ライブ取引切替
- 通知・ログ・日次サマリ

**やらない範囲（初期）**
- 仮想通貨の本格対応
- 高度な機械学習によるシグナル生成（後から差し込み可能にする）
- UIダッシュボード（必要になれば後付け）

---

### 3. アーキテクチャ概要

```
ZeroTrade
├── Core
│   ├── RiskManager          # 証拠金・ポジション・損失制限の強制
│   ├── PositionSizer
│   ├── OrderManager
│   ├── StrategyRunner
│   └── Notifier
├── Brokers
│   ├── BaseBroker           # 抽象インターフェース
│   ├── OandaAdapter         # FX
│   ├── KabuAdapter / TachibanaAdapter  # 日本株
│   └── (将来) BingXAdapter など
├── Data
│   ├── HistoricalFetcher
│   └── RealtimeFeed
├── Strategies
│   └── (ルールベース戦略群)
├── Backtest
└── Config / State
```

**基本方針**
- 戦略・リスク管理・実行はブローカー実装に依存しない
- ブローカー固有の仕様は各Adapter内に閉じ込める

---

### 4. 主要コンポーネント仕様

#### 4.1 BaseBroker（共通インターフェース）
必須メソッド：
- `connect()` / `disconnect()`
- `get_balance()`
- `get_positions()`
- `place_order()`
- `cancel_order()`
- `get_order()` / `get_open_orders()`
- `get_ticker()`

任意メソッド：
- `set_leverage()`
- `get_ohlcv()`

#### 4.2 RiskManager（最重要）
強制するルール例：
- 1トレードあたりのリスク上限（口座残高のX%）
- 日次・週次最大損失で自動停止
- 証拠金使用率上限
- 同時保有ポジション数上限
- 大相場検知時の取引抑制（ATR急拡大など）

ルール違反時は注文を拒否する（例外を投げる or 結果を返して実行を止める）。

#### 4.3 Strategy
- シグナル生成のみを担当
- 実際の注文判断は RiskManager を必ず経由する
- 初期はルールベース（移動平均・RSIなど）から開始

#### 4.4 OrderManager
- 注文状態の追跡
- 部分約定・キャンセル・利確/損切り管理
- クライアント注文IDの管理

### 5. 技術スタック（初期想定）

| 項目 | 採用 |
|------|------|
| 言語 | Python 3.11+ |
| 非同期 | asyncio / httpx or aiohttp |
| データ | pandas, numpy |
| バックテスト | vectorbt または独自簡易エンジン |
| 設定 | YAML / pydantic |
| 永続化 | SQLite（初期）→ 必要に応じてPostgreSQL |
| 通知 | Discord / Slack / LINE Notify など |

---

### 6. 運用フロー

1. 戦略がシグナルを生成
2. RiskManager がリスクチェック
3. 通過した場合のみ OrderManager 経由で発注
4. 約定・ポジション状態を監視
5. 利確・損切り・強制決済をルールに従って実行
6. 日次でサマリ通知

---

### 7. 拡張方針

- 新しいブローカーは `BaseBroker` を実装するだけで追加可能にする
- 仮想通貨（BingXなど）はメインの対象外としつつ、アダプタ実装の余地を残す
- 戦略は差し替え可能なプラグイン形式にする
