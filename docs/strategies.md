# 戦略

同梱戦略の中身、実測された成績、そして新しい戦略の書き方。

---

## 戦略にできること・できないこと

戦略に許されているのは `Signal` を返すことだけである。ロットを決めることも、注文を出すこともできない。

```
Strategy → Signal → PositionSizer → RiskManager → OrderManager → Broker
           （何を    （いくらで）   （通すか）    （送る）
            したいか）
```

これは意図的な制約である。「今日は調子がいいからロットを上げる」という判断をコードレベルで不可能にしている。戦略クラスからブローカーへ到達する経路は存在せず、テストでも保証している。

戦略が返せる指示は5つ。

| `SignalAction` | 意味 |
|---------------|------|
| `ENTER_LONG` / `ENTER_SHORT` | 新規建て。`stop_loss` を付けること（既定では必須） |
| `EXIT` | 建玉を決済する |
| `UPDATE_STOP` | ストップを引き上げる（トレーリング） |
| `HOLD` | 何もしない |

`UPDATE_STOP` は**引き上げ方向にしか動かない**。買い建玉のストップを下げる操作は損失許容量を後から広げる行為で、リスク管理の前提が崩れる。ブローカー側で拒否している。

## 同梱戦略

### `tokyo_fix` — 東京仲値のフローを狙う

**この戦略だけは、データを見る前に理屈がある。**

日本の輸入企業は決済のためにドルを買う必要があり、その基準が各行が午前9時55分ごろに決める仲値（TTM）である。彼らは価格が有利か不利かで判断していない。必要だから買う。つまり**儲けようとしていない参加者による、時刻の決まった一方向のフロー**がそこにある。歪みが残るとすれば、こういう場所である。

8:00 JST に買い、9:55 JST に手仕舞う。利確は置かず、ATRの倍数でストップだけ置く。

| パラメータ | 既定 | 説明 |
|-----------|------|------|
| `entry_time` | `08:00` | エントリー時刻 |
| `exit_time` | `09:55` | 手仕舞い時刻 |
| `timezone` | `Asia/Tokyo` | 時刻の解釈 |
| `atr_stop_multiplier` | 2 | ストップまでの距離 |
| `side` | `buy` | 方向 |

5分足で使うこと。1時間足では 09:55 を表現できない。

**実測（USD/JPY・独立した2期間・スプレッド0.3銭）**

| | 2024（開発用） | 2025-2026（検定用） |
|---|---|---|
| 仲値 08:00→09:55 | **+29.7%**（PF 1.46） | **+14.4%**（PF 1.27） |
| 単純保有 | +11.6% | +7.8% |
| プラセボ 14:00→15:55 | -0.1%（PF 1.00） | +0.7%（PF 1.01） |

両期間で単純保有を上回り、**プラセボは両期間とも真っ平ら**だった。これは対照として理想的な形である。もし単に上昇相場のドリフトを拾っているだけなら、同じ長さ・同じレバレッジのプラセボも儲かるはずだが、そうなっていない。

エントリー時刻をずらした感度プロファイルも連続していた。

| 開始時刻(JST) | 2024 | 2025-2026 |
|--------------|------|-----------|
| 05:00 | -17.6% | -19.0% |
| 06:00 | -19.3% | -6.5% |
| 07:00 | +53.6% | +38.1% |
| **08:00** | **+29.7%** | **+14.4%** |
| 09:00 | +5.6% | +9.7% |
| 10:00 | +0.7% | -23.3% |

孤立したスパイクではなく、同じ形の山が両期間に現れている。これは信頼度を上げる材料である。

**ただし成否は執行コストに強く依存する。**

| スプレッド | 2024 | 2025-2026 | 単純保有超え |
|-----------|------|-----------|------------|
| 0.3銭 | +29.7% | +14.4% | ○ |
| 0.8銭 | +24.0% | +10.0% | ○ |
| 1.5銭 | +16.2% | +3.8% | × |
| 3.0銭 | +1.2% | -7.8% | × |

8:00 JST は 23:00 UTC で、東京の早朝にあたる。この時間帯は流動性が薄くスプレッドが広がりやすい。**実弾を入れる前に、使うブローカーのこの時刻の実勢スプレッドを必ず確認すること。** 1.5銭を超えるなら、この戦略は成立しない。

なお「五十日（ごとおび）に効果が強い」という通説は2024年では見えたが（勝率67%・t=2.23）、2025-2026年では消えた（勝率48.9%）。採用していない。

07:00 開始のほうが成績は良いが、こちらは24通りをスキャンして見つけたものである。事前に指定した仮説とは扱いが違う（後述）。

### `donchian` — ブレイクアウト順張り

N本高値の更新で買い、N本安値の更新で売る。長期移動平均に逆らわず、**利確を置かない**。順張りは少数の大きな勝ちで多数の小さな負けを賄う構造なので、利確を置くとその「少数の大きな勝ち」を自分で切ってしまう。代わりにシャンデリア・エグジット（保有中の高値からATRの倍数を引いた位置）でストップを追随させる。決済は入りより短い期間のブレイクで素早く行う。

| パラメータ | 既定 | 説明 |
|-----------|------|------|
| `entry_period` | 20 | 入りのブレイク期間 |
| `exit_period` | 10 | 出のブレイク期間 |
| `trend_period` | 100 | 長期トレンドフィルタ |
| `atr_stop_multiplier` | 3 | 初期ストップ |
| `atr_trail_multiplier` | 3 | トレーリング幅 |
| `use_trend_filter` | 有効 | 長期トレンドに逆らわない |
| `min_hour_utc` / `max_hour_utc` | なし | 取引時間帯を絞る |

**実測（1時間足）**

| | 2024（開発用） | 2025-2026（検定用） |
|---|---|---|
| `donchian` 既定 | **+18.8%**（PF 1.37） | **-7.4%**（PF 0.87） |
| ロングのみ | +18.6%（PF 1.64） | -2.1%（PF 0.94） |
| 単純保有 | +8.9% | +10.2% |

開発用データで単純保有の倍を出したが、**検定用データで負けた**。しかもこの +18.8% はパラメータ調整の結果ですらなく、教科書的な既定値（20/10・ATR3倍）のままの数字である。調整していないのに再現しなかった。

原因もデータで裏が取れている。ドリフトを差し引いた「20時間高値ブレイク後の超過リターン」は、2024年では t=+2.09 だったのが2025-2026年では **t=-0.06** と完全に消えていた。もともと18通り試したうちの1つが t>2 だっただけで、多重検定を踏まえれば偶然の範囲だった。

### `sma_rsi` — SMAクロス（最小実装）

短期SMA(20)が長期SMA(50)を**その足で**上抜け、かつRSI(14)が70未満のときにロング。ストップは `終値 − ATR×2`、利確は `終値 + ATR×3`。

**これはエッジがあると主張できる戦略ではない。** 目的は「シグナル→サイズ決定→リスク検査→発注→決済→損益確定」が一周することを確認できる最小の実装である。実測では2024年 -14.8%、2025-2026年 -1.1% と両期間で負けている。

コストゼロで測るとプロフィットファクタがちょうど 1.00 になる。素の勝ち負けが完全に五分ということで、取引コストを払えるだけの偏りを持っていない。

## なぜ `tokyo_fix` だけ再現したのか

3つの戦略の違いは、**偏りをどう見つけたか**にある。

`sma_rsi` と `donchian` は「データを見たら偏りがあった」から始めた。`donchian` は18通りの条件を試して t>2 が1つ出たのを根拠にしている。18回検定して1回 p<0.05 が出るのは偶然の範囲で、実際に検定用データでは消えた。

`tokyo_fix` は逆で、**当てる時刻を先に決めてから測った**。「輸入企業が9:55の仲値で買う」という理屈が先にあり、その時刻を1回だけ検定した。総当たりで見つけた条件は多重検定のペナルティを払うが、事前に指定した仮説は払わない。**この差は決定的である。**

同じ理由で、感度プロファイルの表で 07:00 が 08:00 より成績が良くても、07:00 を採用するのは筋が悪い。それは24通りをスキャンして見つけたもので、`donchian` と同じ立場にある。

新しい戦略を作るときは、**「誰が、なぜ、価格の有利不利を無視して売買しているのか」を先に説明できるか**を自問してほしい。説明できるなら、その仮説は1回の検定として扱える。説明できないなら、見つけた偏りは消えたときに何も残らない。

## 新しい戦略を書く

```python
from zerotrade.models import Signal, SignalAction
from zerotrade.strategies import Strategy, StrategyContext, register_strategy


@register_strategy
class MyStrategy(Strategy):
    name = "my_strategy"

    def __init__(self, *, period: int = 20, **extra: object) -> None:
        if extra:
            raise ValueError(f"未知のパラメータです: {', '.join(sorted(extra))}")
        super().__init__(period=period)
        self.period = period
        # 指標に必要な最小本数。これに満たない間は呼ばれない。
        self.warmup_bars = period + 2

    def generate(self, context: StrategyContext) -> Signal:
        if len(context.candles) < self.warmup_bars:
            return self.hold(context, "ウォームアップ中")

        if context.position is not None:
            return self.hold(context, "保有継続")

        return Signal(
            symbol=context.symbol,
            action=SignalAction.ENTER_LONG,
            strategy=self.name,
            stop_loss=...,  # 既定では必須
            reason="...",  # ログとレポートに出る
        )
```

`config/*.yaml` の `strategy.name` に `my_strategy` を書けば読み込まれる。`zerotrade strategies` で登録済みの一覧が見られる。

### 書くときの注意

**副作用を持たせないこと。** 同じ入力からは常に同じシグナルが出るようにする。インスタンス変数に状態を溜めるとバックテストが再現しなくなる。保有中の情報が要るなら `context.position` と `context.candles` から導出する。

**`stop_loss` を必ず付けること。** `require_stop_loss` が既定で有効なので、付けないと RiskManager に弾かれる。ATR の倍数で置くのが扱いやすい。値幅ベースなので銘柄やボラティリティに依存しにくく、そのストップ距離から PositionSizer がロットを逆算する。

**`reason` を書くこと。** ログ、レポート、ダッシュボードにそのまま出る。後から「なぜこの取引をしたのか」を追えるかどうかが、改善できるかどうかを分ける。

**利確を置くか置かないかを意識すること。** 順張りなら置かないほうがよい。少数の大きな勝ちで負けを賄う構造なので、利確はその源泉を切ってしまう。逆張りなら置いたほうがよい。

### 使える指標

```python
from zerotrade.strategies.indicators import sma, ema, rsi, atr, true_range
```

すべて純Python・Decimal 実装で、**データ不足なら `None` を返す**。0 や直近値で埋めないのは、起動直後に誤ったシグナルが出る典型的なバグを避けるためである。
